# Agent 识别

授权页与 Telegram `/agents` 共用 daemon 的[进程目录](../src/agents/catalog.rs)。它识别当前用户正在运行的程序；未运行且没有保存策略的程序不会作为待安装项目列出。安装向导的八个配置选项与这里独立。

程序名称仅用于发现，不是免审批白名单。新程序默认为“每次询问”；策略绑定操作系统核验的完整可执行文件路径。同名不同路径不共享授权，也不以产品名称证明厂商身份。

## 识别边界

名称必须是操作系统报告的实际可执行文件名，不是 shell 别名、npm 命令或客户端自报名称。表中 CLI 名称只有对应独立可执行程序运行时才直接命中。比如 `dsh` 的 npm 入口是 JavaScript；单独以 `node` 运行时，不能因为命令叫 `dsh` 就长期信任整个 Node 安装。Aider、Hermes 等解释器启动方式同理。

Linux 还识别实际进程中使用的 `claude-desktop`。Claude 原生安装的可执行文件可能位于 `.../claude/versions/<版本号>`；当操作系统进程名为 `claude`，目录结构匹配且文件名是有效语义版本时，按 Claude 展示，仍以实际完整路径建立信任。升级后不同版本路径不会继承旧路径的信任，不根据任意进程标题信任通用解释器。

桌面版或编辑器启动的适配器可以沿进程祖先找到已知宿主；Cline、Roo Code、Kilo 等编辑器扩展按实际宿主路径管理，不把扩展名当作独立进程。远端、容器内或已脱离宿主的进程也不凭名称推断本地身份。

路径无法核验时仍可接受当次请求，桌面“记住我的选择”保持禁用，Telegram 不显示记住按钮。没有读取进程环境变量或完整命令行，也没有把 `node`、`python`、`bun`、`electron`、shell 或通用 `agent` 加入目录。
